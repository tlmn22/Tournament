# temtseen.app

Монгол хэлтэй тэмцээн зохион байгуулах платформ. Next.js App Router, TypeScript, Supabase Auth/PostgreSQL, энгийн CSS ашиглана.

## Ажиллуулах

Node.js 20.9+ шаардлагатай.

```sh
npm ci
# .env.example → .env.local, Supabase URL/publishable key тохируулна
npm run dev
```

Серверийн гаргасан localhost хаягаар нээнэ. Порт 3000 ашиглагдаж байвал Next.js дараагийн портыг сонгоно.

## Хуудсууд

- / — нийтлэгдсэн тэмцээнүүдийн минимал хүснэгт; нэрээр хайх, төлөвөөр шүүх, нэр/хугацаагаар эрэмбэлэх, мөр дээр дарж дэлгэрэнгүй рүү орох.
- /login, /register — имэйл, нууц үгээр нэвтрэх/бүртгүүлэх. Нэвтэрсний дараа «Тэмцээнээ удирдах» холбоосоор админ хэсэгт орно.
- /admin — зөвхөн өөрийн тэмцээний жагсаалт, нийтэлсэн/ноорог тоо.
- /admin/new — спортын төрлөө сонгон тэмцээн үүсгэнэ; ноорог хадгалаад шууд баг нэмэх хэсэгт орно.
- /admin/tournaments/[id] — Багууд → Тоглолтын хуваарь гэсэн хоёр үндсэн алхам; мэдээлэл засах нь Тохиргоо хэсэгт. Нийтлэх/буулгах, баг болон тоглолт/оноо удирдана.
- /tournaments — нүүр хуудастай ижил тэмцээний хүснэгт.
- /tournaments/[id] — хуваарь, үр дүн, багууд, танилцуулга; спортын ангиллаар шүүх. Хуудас харагдаж байх үед 30 секунд тутам, мөн цонх руу буцаж ороход шинэчилнэ.

Тоглолтуудыг гараар товлож, шат/тойргийн нэрийг зохион байгуулагч оруулна. Автомат сугалаа, bracket болон спорт тус бүрийн чансаа тооцоолол энэ хувилбарт ороогүй. Тоглолтын цаг, байршил оруулахгүй, public хуудсанд мөн харуулахгүй. Компани гэсэн тусдаа хэсэггүй; тэмцээндээ шууд баг нэмнэ. Өмнөх company холбоос болон цаг/байршлын өгөгдлийг сангаас устгахгүй.

## Supabase тохиргоо

.env.local файл Git-д орохгүй. Publishable key-г клиент ашиглана; service_role key шаардлагагүй.

Email provider идэвхтэй байна. Имэйл баталгаажуулах шаардлагагүй бол Supabase Authentication-ийн Confirm email тохиргоог унтраана. Код баталгаажуулалт асаалттай болон унтраалттай аль алиныг дэмжинэ. Асаалттай үед URL Configuration → Redirect URLs-д http://localhost:3000/login, http://localhost:3001/login болон production домэйны /login хаягийг нэмнэ.

## Өгөгдлийн сангийн migration

`supabase/migrations/202610220001_tournament_workspace.sql` файлыг зөв Supabase төслийн SQL Editor-т нэг удаа ажиллуулна. Publishable key-ээр SQL migration хийх боломжгүй.

Migration нь одоо байгаа tournaments, tournament_events, companies, teams хүснэгт, мөрүүдийг хадгална. Эдгээр хүснэгт байхгүй шинэ төсөлд үүсгэнэ. Шинэ tournament_fixtures хүснэгт нь энэ интерфэйсийн хуваарь, оноог хадгална. Хуучин matches хүснэгт болон бусад хүснэгт өөрчлөгдөхгүй, хуучин matches-ийн өгөгдөл автоматаар шилжихгүй.

Migration дараах өөрчлөлт хийнэ:

- Ашиглаж буй таван хүснэгтийн одоогийн RLS policies-ийг owner/public дүрмээр солино. Бусад хүснэгтийн policies өөрчлөгдөхгүй.
- Бүртгэлтэй хэрэглэгч өөрийн owner_id-тай тэмцээн үүсгэж, зөвхөн өөрийн тэмцээн болон хүүхэд өгөгдлийг засна.
- Нийтийн хандалт зөвхөн status=published тэмцээн болон түүний ангилал, компани, баг, тоглолтыг уншина.
- Ноорог болон нийтлэлээс буулгасан тэмцээний хүүхэд өгөгдөл мөн нуугдана.
- Хоёр баг нэг ангилалд байх, компани тухайн тэмцээнд байх, оноо бүхэл/сөрөг биш байх зэрэг дүрмийг DB түвшинд шалгана.
- Тоглолтод орсон багийг устгахыг foreign key хориглоно. Эхлээд холбоотой тоглолтыг засах/устгах шаардлагатай.

Migration нь нэг transaction; алдаа гарвал хэсэгчлэн хэрэгжихгүй. Хэрэв өмнө нь хүснэгтүүдэд нэмэлт enum, constraint, trigger нэмсэн бол бодит схемийг нягталж нийцүүлнэ. Дахин ажиллуулах зориулалтгүй; хэрэгжүүлсэн migration-ийг өөрчлөхийн оронд дараагийн migration үүсгэнэ.

Клиентийн /admin хамгаалалт нь зөвхөн харагдацын хамгаалалт. Бодит өгөгдлийн эрхийг Supabase JWT + RLS хэрэгжүүлнэ. SQL-ийг хэрэгжүүлэхээс өмнө хуучин DB policies шинэ эрхийн шаардлагыг хангаж байгаа гэж үзэж болохгүй.

## Шалгалтууд

```sh
npm run lint
npm run typecheck
npm run build
npm run check:db
npm run check:auth
npm run check:tournaments
npm run check:ui
```

- check:db: PGlite дэх тусгаарласан PostgreSQL-д migration, эзэмшигчийн CRUD, өөр хэрэглэгч/зочны хориг, нийтлэлээс буулгах, багийн холбоо, онооны дүрмүүдийг шалгана. Supabase-ийн бодит төслийг өөрчлөхгүй.
- check:auth, check:tournaments: Playwright + Microsoft Edge, Supabase хүсэлтийг дуурайлган ажиллуулна. Бодит бүртгэл, имэйл, тэмцээн үүсгэхгүй. Tournaments тест 320–1440 px дэлгэц болон axe accessibility-г шалгана.
- check:ui: тэмцээний хүснэгт, Улаанбаатарын огноогоор төлөв тооцох, хайлт/шүүлт/эрэмбэлэлт/хуудаслалт, мөр болон keyboard холбоос, хоосон/алдааны төлөв, гар утасны цэс, accessibility шалгана. Supabase хүсэлтийг дуурайлган ажиллуулна.

Браузерын тестэд сервер асаалттай байна. PREVIEW_URL=http://localhost:3001 тохируулж серверийн хаягийг сонгоно (browser тестүүдийн default 3001). BROWSER_CHANNEL=chrome гэж өөрчилж болно. Screenshot-ууд .preview/ хавтаст хадгалагдана (Git-д орохгүй).

## Наадам, оролцогч баг, нийтлэл

Дарааллаар `supabase/migrations/202610220001_tournament_workspace.sql`, дараа нь
`supabase/migrations/202610220002_festival_media_articles.sql` файлыг Supabase SQL Editor-т ажиллуулна.
Хоёр дахь migration нь байр, хэсэг, нийтлэлийн хүснэгт, зураг хадгалах bucket болон эзэмшигчийн эрхийг нэмнэ. Одоо байгаа мөрүүдийг устгахгүй.

Админ урсгал:
1. Наадам үүсгэнэ.
2. УУГ, Оффис эсвэл группийн компани зэрэг оролцогч багуудаа нэр, логотой бүртгэнэ.
3. Спорт, ангилал тус бүрээр тэмцээн нэмнэ (жишээ нь сагс эрэгтэй, волейбол эмэгтэй).
4. Тухайн спорт руу орж оролцогчид харьяалагдах багууд, хэсэг, тоглолтуудыг нэмнэ. Эцсийн байрыг менежер оруулна.
5. Бүх төрлийн оролцооны хүснэгт компанийн төрөл бүрийн админаас өгсөн оноог нэмж, нийт оноогоор эрэмбэлнэ.
6. Нийтлэлүүд хэсэгт наадмын тойм, нүүр зураг, 12 хүртэл нэмэлт зурагтай нийтлэл бичнэ. Ноорог хадгалах, урьдчилан харах, нийтлэх боломжтой.

Зураг: PNG/JPEG/WebP, нэг файл 5 MB хүртэл. `tournament-media` public bucket-д `наадмын-id/random-id.ext` замаар хадгална.
Зөвхөн наадмын эзэмшигч тухайн хавтсанд файл бичнэ. Зургийн URL нь public тул ноорогт оруулсан зураг ч холбоосоор нээлттэй; нийтлэлийн ноорог текст RLS-ээр хамгаалагдана.
Зургийг формоос хасахад холбоосыг салгана, хадгалсан файлыг автоматаар устгахгүй.

`npm run check:db` нь хоёр migration, нийтлэл болон зурагт хандах эрхийг локал PostgreSQL орчинд шалгана.
`npm run check:tournaments` нь лого, олон спортын багууд, байр, тоглолт, зурагтай нийтлэл, public урсгал болон responsive/a11y-г mock Supabase ашиглан шалгана.

## Тоглолт автоматаар үүсгэх

Спортын тэмцээн → Тоглолтын хуваарь → Урьдчилан харах. Хэсэг тус бүр дотроо, эсвэл бүх баг нэг тойргоор тоглох хослолыг гаргаж, «N тоглолт үүсгэх» товчоор хадгална. Баг бүрийн хослол нэг удаа орно; сондгой тоотой үед багууд ээлжлэн өнжинө. Хэсгээр үүсгэхэд бүх баг хэсэгтэй, хэсэг бүр хоёроос доошгүй багтай байна. 4/3/3/3 багтай A–D хэсэг нийт 15 тоглолттой.

Өмнө бүртгэсэн хослолыг хоёр багийн ID-аар шалгаж алгасана (гэрийн/зочин дараалал болон шатнаас үл хамаарна). Оноо, тоглолт, хэсгийн хуваарилалтыг дарж өөрчлөхгүй. Бүртгэлтэй тойрогт нэг баг дахин тоглохоор байвал засахыг сануулна. Энэ нь нэг тойргийн хослол үүсгэнэ; давхар тойрог болон хасагдах шатыг автоматаар үүсгэхгүй. Нэг удаагийн тооцоолол 1000 хүртэл хослолтой.

Хадгалахын өмнө баг, тоглолтын мэдээллийг дахин уншина; өөрчлөгдсөн бол шинэчилсэн жагсаалтыг шалгуулаад дахин товч дарахыг шаардана. Бүх тоглолтыг нэг INSERT хүсэлтээр хадгална. Тогтвортой UUID нь автомат үүсгэгчийн давтан/зэрэгцээ хүсэлтийг primary key-ээр хамгаална; upsert ашиглахгүй. Өөрчлөлт нь одоогийн хүснэгт болон эзэмшигчийн RLS-ийг ашиглана, нэмэлт migration шаардлагагүй.

Шалгалт:
- npm run check:fixtures — Node.js 24; хослол/тойргийн логик, хэсэг, өнжих баг, хуучин оноо, давтан хадгалалт болон PostgreSQL transaction/RLS (PGlite).
- npm run check:fixtures:ui — localhost:3001 дээр Playwright; урьдчилан харах, болих, өгөгдлийн өөрчлөлт, давхар даралт, хадгалалтын алдаа, responsive/a11y. Supabase хүсэлтүүдийг дуурайлгана; бодит өгөгдөл өөрчлөхгүй.

## Хэсгийн үр дүнгийн хүснэгт

Нийтийн тэмцээн → Үр дүн → Хэсгийн хүснэгт. Хэсэгтэй багуудын дууссан тоглолтыг спорт, хэсэг тус бүрээр мөр/баганын хүснэгтэд харуулна. Мөрийн багийн оноо эхэнд, баганын багийн оноо дараа орно; өндөр оноо ногоон, өөрийн багийн нүд бараан, үр дүнгүй хослол «—» байна.

Нэг хос баг олон удаа тоглосон бол тоглолт бүрийг тойргийн нэртэй нь тусад нь харуулна. Хэсэг хоорондын болон хэсэггүй багийн тоглолтыг «Тоглолтын жагсаалт»-аас үзнэ. Хэсэггүй ангилалд хуучин жагсаалт шууд харагдана. Хэсгийн матриц тоглолтын онооноос багийн эцсийн байрыг автоматаар тооцохгүй.

npm run check:groups нь онооны хоёр чиглэл, 0 оноо, тэнцээ, давтан тоглолт болон спорт/хэсгийн тусгаарлалтыг шалгана. npm run check:tournaments нь хэсгийн хүснэгт, ангиллын шүүлтүүр, жагсаалт руу шилжих, responsive болон accessibility-г мөн шалгана.

## Компанийн төрөл бүрийн оноо, нийт дүн

Одоо «Бүх төрлийн оролцоо» хүснэгтэд компанийн нэр, төрөл бүрийн админаас өгсөн оноо, нийлбэр, байр харагдана. Нэг компанийн А/Б зэрэг спортын багуудын дүнг автоматаар нэмэхгүй: админ компанид тухайн ангилалд нэг оноо өгнө. Тоглолтын оноо, шатрын result_points, эцсийн байр үүнээс тусдаа хэвээр.

Суулгах: одоогийн төслийн Supabase SQL Editor-т supabase/migrations/202611060001_company_event_points.sql файлыг ажиллуулна. Шинэ company_event_points хүснэгт, эзэмшигчийн RLS болон нэг transaction-оор хадгалах set_company_event_points функцийг үүсгэнэ. Өмнөх тоглолт, баг, оноог өөрчлөхгүй; migration-ийг дахин ажиллуулж болно. Migration хийгдээгүй үед сайт нээгдэнэ, харин админы шинэ оноо хадгалах удирдлага идэвхгүй байна.

Админ → тэмцээн → Бүх төрлийн оролцоо → Компани сонгох (эсвэл хүснэгтийн «Оноо засах») → төрөл бүрийн оноо → Оноо хадгалах. 0–9999, хоёр хүртэл аравтын орон зөвшөөрнө. Хоосон талбар нь оноо өгөөгүй; өмнөх оноог хоослоод хадгалбал арилна. 0 оноо бол бодитоор өгсөн оноо.

Нийт оноо ихээс бага руу эрэмбэлнэ. Тэнцвэл ижил байр (1, 1, 3); ижил байртай компаниуд нэрээрээ дарааллана. Ямар ч оноо оруулаагүй компанид нийт болон байр «—» байна. Төрөл бүрийн дутуу оноо «—» хэвээр, оруулсан оноонуудын нийлбэрийг харуулна.

Зөвхөн тэмцээний эзэмшигч хадгална. Нийтэлсэн тэмцээний оноог зочин уншина. Нэг компанийн бүх өөрчлөлт, арилгалт хамт хадгалагдана; өөр цонхноос өөрчилсөн утгыг дарж бичихгүй. Өөрчлөгдөөгүй нүдийг серверт илгээхгүй.

npm run check:points — нийлбэр/байр, PostgreSQL migration, эрх, transaction, давхар засвар, утгын шалгалт.
npm run check:tournaments — оруулах/засах/арилгах/0 оноо, алдааны дараах дахин хадгалалт, зочны хүснэгт, responsive/a11y. Бодит Supabase өгөгдлийг өөрчлөхгүй.
